Why another subtitle translator?

Tools like Bazarr and Lingarr translate subtitle files that already exist on disk. They can't help when the only English subtitle is embedded inside the video or is a PGS bitmap, which is common on Blu-ray rips. translAItarr2 handles those cases:

✓
Extracts and translates embedded text subtitles straight from the video
✓
OCRs PGS (Blu-ray bitmap) subtitles to text, then translates them
✓
Skips files that already have your language, whether as audio, an embedded sub or a sidecar
✓
Picks the best source language by your priority: English first, then French, German…

Features

Built for people who already run an *arr stack and want every title in their language, without babysitting it.

Native Sonarr/Radarr

Talks to their REST API directly, so you see real series, episode and movie titles. No webhook is needed, and path remapping auto-detects your root folders.

Fully automatic

A periodic scan translates anything new. It re-translates when a release gets upgraded, and you can still run per-title or bulk jobs by hand.

13 engines, with fallbacks

Choose a primary engine plus two fallbacks, which can be from different providers. Set batch sizes and daily limits per model, and override the provider for any single job.

Translation verification

An optional check samples the result and has a model judge each line's meaning against the source. It tolerates paraphrase and flags only lines that are genuinely wrong.

A web UI, not a config file

A setup wizard, a Library view, a live Queue with per-model usage and a live log, and Settings that save themselves. Includes a dark and a light theme.

Private by design

Your keys stay in your config volume and are redacted from logs. The app runs as a non-root user. The only data that ever leaves your server is an anonymous instance counter, and you can switch it off.

Quick start

You don't need to clone anything, because the image is published to GitHub Container Registry.

1

Create a docker-compose.yaml:

services:
  translaitarr2:
    image: ghcr.io/trelowney/translaitarr2:latest
    container_name: translaitarr2
    environment:
      - PUID=1000           # your user id   (run `id` on the host)
      - PGID=1000           # your group id
      - TZ=Europe/Prague    # your timezone
    volumes:
      - ./config:/config            # settings, queue + your API keys
      - /path/to/media:/data        # the library Sonarr/Radarr manage
    ports:
      - 9878:9878
    restart: unless-stopped
2

Set your media path and PUID/PGID/TZ, then start it:

docker compose up -d
3

Open http://<your-server>:9878 and follow the setup wizard. It connects Sonarr/Radarr and your translation engine and sets your languages. Already running an *arr stack? Add the service to the same compose file and use names like http://sonarr:8989.
